# 잡코리아 PM 포트폴리오 가이드 분석과 Life Quiz 적용

참고: [서비스 기획자 포트폴리오, '판단'이 보여야 합격합니다](https://www.jobkorea.co.kr/recruit/careers/articles/product-manager-portfolio-guide)

## 1. 가이드의 핵심

가이드가 반복해서 요구하는 것은 기능 목록이나 산출물의 양이 아니라, 문제를 정의하고 선택을 내린 사람의 판단 과정이다. 프로젝트마다 아래 다섯 단계를 짧고 연결된 이야기로 보여줘야 한다.

1. 문제 정의: 지표 또는 관찰 신호에서 원인을 좁혀 문제 문장으로 만든다.
2. 가설: 어떤 방향이 왜 문제를 풀 것인지와 성공 기준을 적는다.
3. PRD·설계: 전체 문서를 붙이지 않고 핵심 정책 세 줄과 판단이 담긴 화면 하나만 보여준다.
4. 출시: 협업, 제약, 포기한 범위, 트레이드오프를 설명한다.
5. 임팩트: 수치 결과와 함께 무엇을 배웠고 다음에 무엇을 바꿀지 적는다.

수치가 없을 때는 성과를 만들지 말고 검증 결과, 학습, 다음 행동을 제시해야 한다. 제출물은 PDF가 중심이고 Notion은 상세 근거 링크로 쓰는 편이 안정적이다. 첫 30초 안에는 프로젝트의 문제, 본인 역할, 핵심 판단, 결과가 보여야 한다.

## 2. 기존 Life Quiz PDF의 강점

- 서비스 컨셉, 기능, 기술 구조가 10쪽 안에 정리돼 있다.
- Quick Read, Deep Read, FSRS, Gemini 배치 등 차별점이 보인다.
- 실제 운영 수치와 무료 티어 설계가 들어 있다.
- 수집량 감소, 자치구 반복, 4컷 중복 같은 개선 사례가 있다.

## 3. 기존 자료의 부족한 점

### 문제와 원인의 연결이 약함

사회초년생의 정보 문제는 설명하지만, 어떤 관찰을 근거로 어떤 원인을 선택했는지와 검증 상태가 드러나지 않는다. 인터뷰로 확인한 사실과 기획 가설도 구분되지 않는다.

### 기능이 가설보다 앞에 보임

홈, 보관함, 챗, 시작 코스 등 화면은 많지만 각 기능이 어떤 가설을 검증하려고 만들어졌는지 빠르게 읽히지 않는다.

### 출시 과정의 포기와 순서가 약함

무료 운영 구조는 설명하지만 정식 로그인, 실시간 생성, 투자 추천, AI 이미지 등을 왜 미뤘는지는 흩어져 있다.

### 시스템 결과와 사용자 성과가 섞임

콘텐츠 수, 테스트 수, D1 사용량은 구현·운영 결과다. 사용자 완료율, 재방문율, 기억 효과와 같은 제품 성과를 대신하지 못한다. 기존 PDF는 이 경계를 더 명확히 해야 한다.

### 해결과 진행 중 상태가 섞임

콘텐츠 다양성 자동 복구를 출시했지만 2026.08.01 실제 피드는 9건·3/12개 분야다. 기능을 출시했다는 사실과 목표를 달성했다는 결론을 분리해야 한다.

## 4. 새 문서에 반영한 방식

| 가이드 요구 | 새 포트폴리오 반영 |
| --- | --- |
| 첫 30초에 핵심 판단 | 2쪽에 Problem·Decision·Value와 핵심 수치, 미검증 상태를 함께 배치 |
| 문제 정의 | 3쪽에서 문제 문장과 인터뷰 전 제품 가설임을 명시 |
| 가설과 성공 기준 | 4-6쪽 사례마다 가설, 핵심 PRD, 트레이드오프, 현재 결론을 고정 순서로 작성 |
| 핵심 화면만 사용 | 5분 학습 실제 화면 한 장만 크게 사용 |
| 출시와 협업 | 무료 티어, Service Binding, 익명 우선, 미룬 기능을 판단 근거와 함께 설명 |
| 임팩트 | 산출물·품질·사용자 성과를 별도 층으로 분리 |
| 수치가 부족한 경우 | 사용자 성과 미검증을 명시하고 4주 계측·과업 테스트 계획 제시 |
| 1쪽 의사결정 맵 | 별도 `Life_Quiz_Decision_Map_2026-08.pdf` 제공 |
| Notion 보조 자료 | 상세 사례와 수치 근거 대장을 프로젝트 디렉터리 아래에 생성 |

## 5. 지원할 때의 사용 순서

1. 지원서에는 `Life_Quiz_PM_Portfolio_2026-08.pdf`를 첨부한다.
2. 이력서 프로젝트 항목에는 공개 서비스와 GitHub 링크를 함께 넣는다.
3. Notion 상세 사례 링크는 PDF 마지막 페이지나 이력서 링크 영역에 둔다.
4. 면접 직전에는 1쪽 의사결정 맵과 수치·근거 대장만 다시 본다.
5. 제출 당일에는 운영 수치를 다시 조회하고 날짜가 달라졌으면 PDF 수치를 갱신한다.

## 6. 다음 보강에 필요한 근거

- 사회초년생 5명의 과업 테스트 기록
- 홈 방문 대비 5분 학습 시작률
- 첫 문제 응답률과 5개 완료율
- 첫 완료 후 7일 복습 재방문율
- SOURCE 클릭률과 출처 신뢰 이유
- 18시 이후 일일 분야 커버리지와 단일 분야 점유율

이 여섯 가지가 쌓이면 다음 버전에서는 시스템 구축 사례를 사용자 행동 변화 사례로 확장할 수 있다.
